# 机械革命控制中心「系统选项」模块逆向分析报告

> 分析对象：ControlCenter 5.56.60.34（Mechrevo GX 定制版）
> 分析方法：静态反编译（ILSpy / ilspycmd）+ 字符串堆与元数据提取 + 配套进程源码级还原 + 本机运行时环境取证
> 分析日期：2026-11-02

---

## 0. 结论速览

1. 「系统选项」在程序内部是 `QuickSwitchPage`（导航枚举 `NavigationItemType.SystemSetting`），**自身不实现任何系统操作**，只负责把开关点击翻译成 MQTT 动作字符串。
2. 真正的执行者是后台服务 `GCUService.exe`。它把四类开关分流到**四条完全不同的技术通道**：Windows Radio API、PowerShell/PnP、ACPI-WMI 固件接口（MIFS）、自研虚拟 HID 驱动（`\\.\Vhidcontrol`）。
3. 本机运行的**不是**官方 GCUService，而是移植项目自建的 `JiaoLongCCUBridge`（LocalSystem）。因此「系统选项」的落地路径与官方设计**部分等价、部分退化**：WiFi/蓝牙/摄像头改为禁用 PnP 设备，触摸板/Fn 锁走固件 MIFS，而 **Win 键锁与 OSD 开关在本机是纯状态记忆，点开无效**。

## 2. 总体架构

```
┌──────────────────────────────┐
│ CCUWinUI.exe (MSIX/AppContainer)
│  QuickSwitchPage + ViewModel │
└───────────┬──────────────────┘
            │ MQTT 127.0.0.1:13688
            │  publish: Setting/Control {"Action":"WIFI_OFF"}
            │  subscribe: Setting/Status, Settings/DeviceSwitchItemStatus
┌───────────▼──────────────────┐
│ 后台服务（官方 GCUService.exe / 本机 JiaoLongCCUBridge）
│  DeviceSwitchItem 分发器
└───┬─────────┬──────────┬─────┴───────┬──────────────┐
    │         │          │             │              │
 Radio API  PowerShell  ACPI-WMI     \\.\Vhidcontrol  注册表
 (WiFi/BT)  /PnP        MIFS fn11/12  (虚拟HID)       ItemSupport/MySetting
            (摄像头)    (Fn锁/触摸板)
```

### 2.1 主题与责任划分

| MQTT 主题 | 方向 | 作用 |
|---|---|---|
| `Setting/Control` | UI → 服务 | 所有系统选项动作下发 |
| `Setting/Status` | 服务 → UI | 回发 WinKey / OSD / NumPad / FnKey / CopilotKey / Uni / Omni |
| `Settings/DeviceSwitchItemStatus` | 服务 → UI | 回发四个设备开关：`WIFIEnable`、`BTEnable`、`WebCamEnable`、`TochpadEnable` |
| `TouchpadToggle/Control` / `Status` | 双向 | 触摸板锁定（快捷键语义）独立通道 |
| `BT_LC/Control` / `Status` | 双向 | 蓝牙低功耗（外设灯效类，非开关） |
| `Languages/Control` | UI → 服务 | 语言切换 |

> **[直证]** `TochpadEnable` 的拼写错误同时存在于 UI 反编译代码（`QuickSwitchViewModel.DataChange` 中 `TouchSwitch = Support.TochpadEnable`）与桥接实现注释「源码拼写如此」。这是判断两条代码同源的硬指纹。

### 2.2 UI 侧的完整动作映射

`QuickSwitchViewModel.ShortcutItemSwitchStatus(tag, status)` 是唯一出口，逻辑为纯字符串拼装：

| UI tag（资源键） | 中文项 | 下发动作 |
|---|---|---|
| `strwdWifiSwitch` | Wi-Fi | `WIFI_ON` / `WIFI_OFF` |
| `strwdBluetoothSwitch` | 蓝牙 | `BT_ON` / `BT_OFF` |
| `strwdWebcamSwitch` | 摄像头 | `WEBCAM_ON` / `WEBCAM_OFF` |
| `strwdTouchpadSwitch` | 触摸板 | `TOUCHPAD_ON` / `TOUCHPAD_OFF` |
| `strWinKey` | Windows 键 | `WINKEY_LOCK` / `WINKEY_UNLOCK` |
| `strOSD` | OSD 显示 | `OSD_HIDDEN_ON` / `OSD_HIDDEN_OFF` |
| `strFnKey` | Fn 键 | `FNKEY_LOCK` / `FNKEY_UNLOCK` |
| `strNumPad` | 数字键盘 | `NUMPAD_LOCK` / `NUMPAD_UNLOCK` |
| `strCopilotKey` | Copilot 键 | `COPILOTKEY_LOCK` / `COPILOTKEY_UNLOCK` |
| `strTouchpadToggle` | 触摸板锁定 | `TOUCHPAD_TOGGLE_ON` / `_OFF` |

**关键设计**：UI 从不检查"操作是否成功"，只在收到服务端回发的状态主题后刷新开关。因此**任何服务端未实现的动作，在界面上表现为"点了会弹回"或"永久保持"，不会报错**。

## 3. 关键设置项的生效逻辑

### 3.0 前置：能力门控（决定"显示不显示"）

`QuickSwitchViewModel.RefreshItemSupport()` 从注册表读取机型能力位，全部来自：

```
HKLM\SOFTWARE\OEM\GamingCenter2\ItemSupport
```

| 键 | 作用 |
|---|---|
| `NumPadSupport` | 是否显示数字键盘开关 |
| `BIOS_PROJECT_ID` | 机型代号；命中白名单（IDA/IDB/ID6/IDQ…）则**强制关闭**「触摸板锁定」项 |
| `APVersionCheck` | ≥24 才允许显示 Copilot 键 |
| `LocalDimmingSupport` | 局部调光 |
| `MicNoiseReductionSupport` | 麦克风降噪（Uni/Omni） |
| `micNoiseReductionType`（在 `MySetting` 下） | =2 时才显示 Uni |

另有 `customizeTarget` 硬编码分支：`45` 隐藏全部设备开关；`11`/`27` 关闭数字键盘；`27` 强制 MiniPC 模式。

---

### 3.1 Wi-Fi

**服务端实现**：`GCService5.DeviceSwitchItem`

- **[推证]** 初始化 `InitializeWifiRadio()` 的 async 状态机持有 `TaskAwaiter<IReadOnlyList<Radio>>` → 调用 `Radio.GetRadiosAsync()`，按 `RadioKind.WiFi` 选出 `WIFIModel`。
- **[推证]** 开关方法 `SetwifiStatusAsync(bool IsOn)` 的状态机只有 `TaskAwaiter<RadioAccessStatus>` 一个 await → 只可能是 `WIFIModel.SetStateAsync(IsOn ? RadioState.On : RadioState.Off)`。这是 `Windows.Devices.Radios` 里唯一返回该类型的方法。
- **[直证]** 订阅 `WIFIModel.StateChanged`（`WIFIModel_StateChanged`），系统侧状态变化（Fn 快捷键、Win11 快捷面板、飞行模式）时回调 `UpdateToClient()`，发布 `Settings/DeviceSwitchItemStatus`。

**语义**：这是**软射频开关**，等价于系统「飞行模式」里的 Wi-Fi 磁贴。网卡仍在设备管理器里，只是无线电被关闭，功耗最低、恢复最快。

**门控**：`wifilock` 字段用于串行化并发点击。

---

### 3.2 蓝牙

与 Wi-Fi 同构，但初始化走另一条路：

- **[推证]** `InitializeAsync()` 同时持有 `TaskAwaiter<DeviceInformationCollection>` 与 `TaskAwaiter<Radio>` → 先用 `DeviceInformation.FindAllAsync(Radio.GetDeviceSelector())` 枚举，再逐个 `Radio.FromIdAsync(id)`。这是微软官方示例中处理"USB 蓝牙适配器不在 `GetRadiosAsync()` 结果里"的标准写法。
- **[推证]** `SetBTStatusAsync(bool IsOn)` → `BTModel.SetStateAsync(...)`，同样返回 `RadioAccessStatus`。
- **[直证]** 订阅 `BTModel.StateChanged` 做反向同步。

---

### 3.3 摄像头

唯一不走 WinRT 的一项，改用 **PowerShell + PnP**：

**[直证]** 常量字符串（编译进元数据，未被保护器清除）：

```powershell
# 启用
Enable-PnpDevice  -InstanceId (Get-PnpDevice -FriendlyName *Webcam* -Class Camera -Status Error).InstanceId -Confirm:$false
# 禁用
Disable-PnpDevice -InstanceId (Get-PnpDevice -FriendlyName *Webcam* -Class Camera -Status OK).InstanceId    -Confirm:$false
# 状态查询
Get-PnpDevice -FriendlyName *webcam* -Class Camera -Status OK
```

同目录 `Command\enableWebcam.ps1` / `disableWebcam.ps1` 为同一逻辑的落盘脚本，且比常量多一条 `*Camera*` 匹配：

```powershell
Enable-PnpDevice -InstanceId (Get-PnpDevice -FriendlyName *Camera* -Class Camera -Status Error).InstanceId -Confirm:$false
```

**方法与状态的三段式**（由方法名直证）：

| 方法 | 作用 |
|---|---|
| `InitCamStatus()` | 执行 `Get-PnpDevice ... -Status OK`，有输出即视为"开" |
| `UpdateECCamStatus()` | 执行 Enable/Disable，并**同步写 EC RAM** |
| `UpdateECCamStatusS4()` | 从 S4（休眠）唤醒后重新对齐 PnP 与 EC 状态 |

`InitEcCamStatus()` + 字段 `MyEcCtrl EcCtrl`、`WMIEC m_Wmi` 说明摄像头开关状态在 EC 里有一份副本，用于掉电/休眠后恢复。这是因为 PnP 设备状态在 S4 后可能被驱动重枚举，需要 EC 侧兜底。

**[直证]** 该类还有 `SetCamSwitch` 与 `ExecuteCommand` 两个方法，后者是 PowerShell 的通用执行入口，印证"脚本字符串常量化 + 运行时调用"的实现方式。

**语义**：**硬禁用设备**——设备从设备管理器消失，任何应用都无法调用。

### 3.4 触摸板（三个不同语义的开关，最容易混淆）

| 动作 | 语义 | 服务端实现 |
|---|---|---|
| `TOUCHPAD_ON` / `TOUCHPAD_OFF` | 系统选项里的「触摸板」开关 = 启用/停用触摸板 | `SetTouchpadSwitch(bool)` **[推断]** 写 `HKCU\Software\Microsoft\Windows\CurrentVersion\PrecisionTouchPad\Status\Enabled` |
| `TOUCHPAD_TOGGLE_ON` / `_OFF` | 快捷键语义的"锁定触摸板" | 独立主题 `TouchpadToggle/Control`，另一套处理 |
| `TOUCHPAD_LED_ON` / `_OFF` | **仅控制触摸板指示灯**，不改功能 | 由 `OSDTpDetect.exe` 发出 |

**关键旁证（未加密的 `OSDTpDetect.exe`）**：

```csharp
private string m_RegistryPath =
    "software\\Microsoft\\Windows\\CurrentVersion\\PrecisionTouchPad\\Status";

registryMonitor = new RegistryMonitor("HKEY_CURRENT_USER\\" + m_RegistryPath);
registryMonitor.RegChanged += OnRegChanged2;
registryMonitor.Start();
```

`OnRegChanged2` 读 `Enabled`：
- `>0` → 发 `Setting/Control {Action:"TOUCHPAD_LED_ON"}` 并弹 "Touchpad on" OSD
- `=0` → 发 `TOUCHPAD_LED_OFF` 并弹 "Touchpad off"

**结论**：触摸板的"开/关"真正的事实源是 **Windows 自己的 Precision Touchpad 状态**。控制中心不抢这个所有权，而是**跟随**它并同步指示灯与 OSD。这也解释了为什么该模块要单独做一个常驻进程：必须有人监听注册表变化（用户按 Fn 快捷键、或用 Windows 设置关触摸板）。

`TriggerTouchpad()` 则是主动触发一次同步（重新读状态 → 发 LED 指令）。

### 3.5 Windows 键 / Fn 键 / 数字键盘

这三项在服务端都指向**键盘扫描码级**的控制，而非软件钩子。

**[直证]** 字符串堆中的设备通道：

```
\\.\Vhidcontrol
 /GGYY7878
```

- `\\.\Vhidcontrol` 是 OEM 自研的**虚拟 HID 控制驱动**设备名，第二个常量是 CreateFile 的附加参数（口令）。
- 该通道用于 `WINKEY_LOCK` / `WINKEY_UNLOCK` / `COPILOTKEY_LOCK` / `COPILOTKEY_UNLOCK`：通过虚拟键盘设备屏蔽/放行特定键的扫描码，效果是**内核级**的，任务管理器、其他软件都无法绕过。
- 同时存在 `TouchPadWorkArea/Control` 主题，说明该驱动还承担触摸板工作区（防误触区域）配置。

**Fn 键**走另一条路：ACPI-WMI 固件接口（MIFS）。

**[直证]** 配套 `OSDTpDetect.exe` 内 `MyECIO.AcpiCtrl` 完整实现：

```
设备：\\.\ACPIDriver
IOCTL_GPD_ACPI_CUSTOMCTL = 2621482244  (0x9C40_4044)
Read("WMIEC", addr, ref byte)
```

这是 GPD 风格的 ACPI 透传驱动，`Read/Write(name, addr, data)` 直接读写 EC/ACPI 空间。

**[直证]** 桥接服务 `Mifs.cs` 的功能号表（源自第三方程序反编译 + 本机实测）：

```
fn11 = Fn 锁（0=未锁 1=锁定）
fn12 = 触摸板锁（0=开 1=锁）
```

所以 Fn 键锁定 = **写固件寄存器**，生效于 EC 层，重启后仍保持（由 EC 记忆）。

**数字键盘（NumPad）**：`NUMPAD_LOCK/UNLOCK`，在服务端由 EC 控制小键盘区（部分机型是触摸板区域虚拟数字键）。未在字符串堆中发现独立设备通道，推测同样走 EC **[推断]**。

### 3.6 OSD 显示开关

`OSD_HIDDEN_ON` / `OSD_HIDDEN_OFF`，落点是注册表：

**[直证]** `OSDTpDetect.exe`：

```csharp
private string m_OsdHiddenPath = "SOFTWARE\\OEM\\GamingCenter2\\MySetting";
// 读 OSDHidden，==1 表示隐藏
m_bOsdSwitch = !LoadOsdSwitchStateFromRegistry();
```

即写 `HKLM\SOFTWARE\OEM\GamingCenter2\MySetting\OSDHidden`。所有 OEM 的 OSD 进程（OSDTpDetect、GamingCenterU）启动时读这个值决定是否弹窗。

## 4. 本机环境对应分析

### 4.1 硬件事实

| 部件 | 型号 | 证据 |
|---|---|---|
| CPU | Ryzen 7 7745HX（8C16T） | 既有项目记录 |
| Wi-Fi | **RZ608 Wi-Fi 6E 80MHz**（MediaTek MT7922） | `PCI\VEN_14C3&DEV_0608` |
| 蓝牙 | **RZ608 Bluetooth(R) Adapter** | 与 Wi-Fi 同一模块 |
| 摄像头 | Integrated Camera（另有 Virtual Camera） | `Get-PnpDevice -Class Camera` |
| 触摸板 | I2C HID 设备 / 符合 HID 标准的触摸板 | 精密触摸板，`Enabled = 1` |
| 固件接口 | `ACPI\PNP0C14\MIFS_0` 可枚举 | `root/WMI` → `MICommonInterface` |

### 4.2 软件栈（**与官方设计的关键偏离**）

| 组件 | 官方设计 | 本机实际 |
|---|---|---|
| UI | CCUWinUI（OEM 签名 MSIX） | CCUWinUI 5.56.60.34，**CN=JiaoLongCCU-Port 自签名** |
| 服务 | `GCUService.exe`（Windows 服务） | **未安装、未运行** |
| 后端 | GCUService | **`JiaoLongCCUBridge`，LocalSystem，Running** |
| MQTT broker | GCUService 内嵌 13688 | 桥接内嵌 13688（同端口同主题） |
| 固件通道 | `\\.\ACPIDriver` (GPD IOCTL) | `root\WMI` → `MICommonInterface`（等效 ACPI-WMI） |
| 虚拟 HID | `\\.\Vhidcontrol` | **未发现该设备/驱动** |

> 桥接服务日志 `C:\ProgramData\JiaoLongCCUBridge\bridge_*.log` 显示：UI 每次进入系统选项页面会发 `GETSTATUS`，桥接回 `{"WIFIEnable":true,"BTEnable":true,"TochpadEnable":true,"WebCamEnable":true}`，与当前实际状态一致。

### 4.3 本机能力位（`HKLM\SOFTWARE\OEM\GamingCenter2\ItemSupport`）

| 键 | 值 | 对系统选项的影响 |
|---|---|---|
| `BIOS_PROJECT_ID` | **ID6** | 命中白名单 → **「触摸板锁定」项被隐藏** |
| `NumPadSupport` | 0 | 数字键盘项隐藏 |
| `MicNoiseReductionSupport` | 0 | Uni / Omni 隐藏 |
| `APVersionCheck` | 0 | Copilot 键隐藏（需 ≥24） |
| `LocalDimmingSupport` | 0 | 局部调光隐藏 |
| `IsNewUMASupport` | 0 | 不走新 UMA 分支 |
| `IsAMDPlatform` | 1 | AMD 平台分支 |
| `customizeTarget` | 56 | 不触发任何隐藏分支 |

**因此本机「系统选项」实际只显示 7 项**：摄像头、触摸板、蓝牙、Wi-Fi、Windows 键、OSD、Fn 键。

### 4.4 逐项落地对照

| 设置项 | 官方实现路径 | 本机实际路径 | 是否真实生效 |
|---|---|---|---|
| **Wi-Fi** | `Radio.SetStateAsync` 软射频开关 | 桥接 `DeviceToggles.SetEnabled("wifi")` → `CM_Disable_DevNode` **禁用 RZ608 网卡** | ✅ 生效，但**语义不同**（见 §5） |
| **蓝牙** | `Radio.SetStateAsync` | `CM_Disable_DevNode` 禁用 `RZ608 Bluetooth(R) Adapter` | ✅ 生效，语义不同 |
| **摄像头** | PowerShell `Disable-PnpDevice` + EC 备份 | `CM_Disable_DevNode` 禁用 Camera 类设备 | ✅ 生效（会连 Virtual Camera 一起禁用） |
| **触摸板** | 写 PrecisionTouchPad 状态 + LED 同步 | `MIFS fn12` 写固件（`SetTouchpadLocked`） | ✅ 生效（固件级，与 Windows 状态**不联动**） |
| **Fn 键** | MIFS fn11（GPD IOCTL） | `MIFS fn11`（ACPI-WMI） | ✅ 生效 |
| **Windows 键** | `\\.\Vhidcontrol` 虚拟 HID 屏蔽扫描码 | 仅 `_state.WinKeyState = "LOCK"` **状态记忆** | ❌ **不生效**（UI 显示已锁，实际 Win 键仍可用） |
| **OSD** | 写 `MySetting\OSDHidden` | 仅 `_state.OsdState = "ON"/"OFF"` | ❌ **不生效**（OSD 进程不存在，也无从读取） |
| 数字键盘 | — | 未显示（`NumPadSupport=0`） | 不适用 |
| 触摸板锁定 | `TouchpadToggle/Control` | 未显示（`ID6` 命中白名单） | 不适用 |
| Copilot 键 | — | 未显示（`APVersionCheck=0`） | 不适用 |

### 4.5 本机状态回读的真实来源

| UI 开关 | 回读来源 | 含义 |
|---|---|---|
| Wi-Fi | `DeviceToggles.QueryEnabled("wifi")` → SetupAPI 查 `CM_PROB_DISABLED` | 只反映"网卡是否被禁用"，**不反映飞行模式/Win11 快捷面板的软开关** |
| 蓝牙 | 同上，匹配 `ClassGuid=Bluetooth` 且名字含 `Adapter` | 同上 |
| 摄像头 | 同上，Camera 类 | 同上 |
| 触摸板 | `MIFS fn12` 回读固件锁定位 | **不读** Windows 的 `PrecisionTouchPad\Status\Enabled` |
| Win 键 / OSD / Fn 键 | 桥接内部 `_state`（JSON 持久化） | 自己记的，可能与硬件真实状态脱节 |

## 5. 差异与风险（本机特有）

1. **Win 键锁与 OSD 开关是"假开关"**
   桥接只写内存/JSON 状态，没有任何驱动或注册表落点。UI 会显示"已锁定"，但 Win 键功能完全正常。这是移植过程中的未实现项，不是 bug 表现（不会报错，也不会弹回）。

2. **Wi-Fi/蓝牙开关的语义被放大**
   官方是"关无线电"（网卡仍在，秒开秒关）；本机是"禁用设备"（网卡从系统移除，需重新枚举，部分 VPN/虚拟网卡驱动可能残留状态）。副作用：
   - 关闭 Wi-Fi 后，Windows 快捷面板的 Wi-Fi 磁贴会消失而非变灰；
   - 若桥接以非管理员运行，`CM_Disable_DevNode` 会失败（本机 LocalSystem，正常）。

3. **摄像头开关会波及虚拟摄像头**
   桥接的 `cam` 匹配条件是 `ClassGuid == Camera`，不判断名字。`Virtual Camera`（OBS/直播软件）与 `Integrated Camera` 同属 Camera 类，会被一并禁用。官方脚本用 `*Webcam*` / `*Camera*` 名字过滤，同样会命中 `Virtual Camera`，属于同源缺陷。

4. **触摸板状态有两个真相源，会不同步**
   本机触摸板开关走固件 fn12，而 Windows 的 `PrecisionTouchPad\Status\Enabled` 由系统自己维护。若用户用 Windows 设置关掉触摸板，控制中心的开关**不会跟着变**（因为没有 `OSDTpDetect.exe` 在监听注册表）。官方设计里这个同步是靠 OSDTpDetect 完成的。

5. **`\\.\Vhidcontrol` 驱动缺失**
   本机驱动表中未发现 OEM 虚拟 HID 控制驱动（仅有第三方 `UUYCInput Virtual HID (VHF)`）。即使换回官方 GCUService，Win 键锁/Copilot 键锁也会因设备打开失败而失效——除非安装 OEM 的驱动包。这一点也解释了移植版为何干脆只做状态记忆。

6. **能力位与实际硬件不完全匹配**
   `ItemSupport` 里 `LocalDimmingSupport=0`、`NumPadSupport=0`、`MicNoiseReductionSupport=0`，说明该机型（ID6）出厂就不带这些功能，UI 隐藏是正确行为，不是缺陷。
