# 系统选项功能完善说明

> 对象：机械革命控制中心（CCU.WinUI 5.56.60.34）「系统选项」页 + 本机后端 `JiaoLongCCUBridge`
> 日期：2026-11-02　验证环境：MRID6 / R7 7745HX / RZ608 / Windows 11

---

## 0. 范围与结论

「系统选项」页由官方 UI（MSIX 封装的 `CCUWinUI.dll`）渲染，**UI 层不改**——它只把开关点击翻译成 MQTT 动作字符串，真正的实现全部在服务端。因此本次完善集中在后端 `JiaoLongCCUBridge`：

- **补全 2 个完全失效的功能**：Windows 键锁定（原为纯状态记忆）、OSD 开关（原为纯状态记忆）
- **修复 3 个落地不完整的功能**：触摸板（只写固件、与系统割裂）、摄像头（误伤虚拟设备）、设备开关（失败无原因）
- **统一了 12 个动作的校验、错误反馈、默认值与持久化**
- 验收：**23 项断言全部通过**（含 Win 键真实按键拦截计数）

## 2. 统一机制

### 2.1 执行结果模型

新增 `ActionResult(Ok, Code, Message)`，所有动作统一返回。分发器改为：

```
执行 → 成功才 Save → 失败发 Setting/Error → 无论成败都回发真实状态
```

**关键设计**：失败时**不写状态**，随后回发的状态就是硬件的真实状态，UI 开关会自动弹回——这就是"操作未生效"的可视反馈（官方 UI 没有错误弹窗能力）。

### 2.2 新增错误主题

```
Topic: Setting/Error
{ "Action":"WEBCAM_OFF", "Code":"DEVICE_FAILED", "Message":"…", "Timestamp":"…" }
```

官方 UI 不订阅（忽略无害），日志与第三方工具可据此定位。错误码：

| Code | 含义 |
|---|---|
| `NOT_SUPPORTED` | 机型能力位不支持 |
| `NOT_IMPLEMENTED` | 能力位支持但无实现通道 |
| `DEVICE_FAILED` | 设备启用/禁用失败（附 cfgMgr32 码） |
| `HOOK_FAILED` | 键盘钩子未就绪 |
| `REG_WRITE_FAILED` / `READBACK_MISMATCH` | 写入或回读校验失败 |
| `MIFS_FAILED` | 固件接口调用失败 |
| `BAD_PARAM` | 参数非法 |
| `UNKNOWN_ACTION` | 未实现的动作 |

### 2.3 防回声（本次实测发现的真问题）

官方 UI 的开关绑定在收到 `Setting/Status` 后会**反向触发一次命令**（收到 `OSD=OFF` → 控件 Unchecked → 发 `OSD_HIDDEN_ON`），服务端再回发状态又触发 UI，实测形成 **~60ms 的乒乓循环**。

处置：
- 服务端记录"最后一次真实设置结果"，1 秒内的**反向**指令判为回声直接返回（`Success`，不改变状态）
- 回灌的状态主题（`Setting/Status`、`Settings/DeviceSwitchItemStatus` 等）在入口丢弃，不再刷 `MSG/IGNORED` 双份日志

### 2.4 默认值与持久化

| 项 | 处理 |
|---|---|
| 状态文件 | 原子写：唯一临时文件 + `File.Replace`，并**串行化**（原来并发 Save 会撞 `file is being used by another process`） |
| 损坏恢复 | 解析失败时备份为 `.corrupt` 再回默认值，不再静默丢弃 |
| 开机恢复 | `RestoreSystemSettings()`：Win 键锁重新拉起钩子、OSD 写回注册表；**触摸板/设备开关不主动改**（尊重系统状态，避免"开机莫名关网卡"） |
| 钩子预热 | 服务启动即拉起钩子进程（空闲不拦截），保证用户点击锁定时 400ms 内生效 |

## 5. 遗留限制

1. **摄像头禁用被驱动否决**
   本机 `Integrated Camera`（USB\VID_2EFE&PID_6460）返回 `CR_REMOVE_VETOED (23)`，系统自带 `Disable-PnpDevice` **同样失败**，属设备/占用方限制而非实现问题。已给出可操作提示；关闭占用摄像头的程序后可重试。

2. **OSD 开关无消费方**
   本机未部署 `OSDTpDetect.exe`，注册表落点正确但当前没有进程读取，因此"关闭 OSD"暂无可见效果。若后续部署官方 OSD 组件即自动生效。

3. **Win 键钩子的固有限制**
   - 需要用户已登录（Session 0 服务无法拦截输入）
   - 安全软件可能拦截全局键盘钩子（已做失败回包 + 守护重试）
   - 只在**当前会话**生效，切换用户需重启钩子（守护定时器会处理）

4. **Wi-Fi / 蓝牙未做破坏性实测**
   禁用会断网/断外设，验收时跳过；代码路径与摄像头同源（同样的 `CM_Disable_DevNode`），风险已由摄像头的失败路径覆盖。

5. **触摸板状态仍有两个真相源**
   双写保证"控制中心操作 → 系统同步"，但反向（用 Windows 设置关触摸板 → 控制中心跟随）需要常驻监听，即官方 `OSDTpDetect.exe` 的角色，本次未实现。
