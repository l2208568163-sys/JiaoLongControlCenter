## 3. 控制链路（G2）

```
CCUWinUI.exe（键盘页）
   │  MQTT publish:  topic=Keyboard/Ctrl   payload=JSON
   ▼
JiaoLongCCUBridge（内置 broker 127.0.0.1:13688）
   │  解析 function → 状态落盘 state.json → 调用 Mifs
   ▼
WMI：root\WMI  class MICommonInterface  method MiInterface(InData, OutData, Reserved)
   │  32 字节请求帧（见 §4.2）
   ▼
wmiacpi.sys → ACPI 命名空间（厂商 MIFS 对象）→ EC（ACPI\PNP0C09）
   │  固件执行：设置键盘灯模式/颜色/亮度
   ▼
键盘背光 LED（本机状态回报 type=FourZone）
```

**旁路（未使用）**：`WinRing0x64.dll` 直接端口 I/O（0x4E/0x4F 扩展寻址、0x66/0x62 命令口）可绕过 ACPI 直接读写 EC RAM。本机 EC 读通道实测不可靠（本机风扇寄存器恒读 0x12），键盘灯**不建议**走此路。

**厂商原生实现（参考）**：反编译源码显示官方服务用 `WMIEC.WMIWriteECRAM(Addr, Value)`、`GetSetULong2(Cmd, Addr, Offset, Value)`、`Smrw(Cmd, Value)`（命令字：读 0xBB / 写 0xAA），属"WMI 写 EC RAM"另一种封装，与 MIFS 函数码通道并存。

## 4. 协议与数据格式（G3）

### 4.1 传输层 A：MQTT（本地回环）

| 项 | 值 |
|---|---|
| Broker | 桥接进程内嵌，`127.0.0.1:13688` |
| 认证 | `UWPClient_User_5` / `UWPClient_Pwd888881772688_5` |
| 下行 topic | `Keyboard/Ctrl` |
| 上行 topic | `Keyboard/Status` |
| 报文 | UTF-8 JSON；建议 QoS1（QoS0 在 broker 重启窗口会丢） |

**下行指令（已实测）**

```jsonc
// 固定颜色（effect=single 时用 color.ColorBuffer[0]）
{"function":"SetEffectALL","effect":"single","light":"2",
 "color":{"ColorBuffer":[{"R":0,"G":128,"B":255}]}}

// 亮度 0..3
{"function":"SetLightingLevel","light":"2"}

// 开关
{"function":"SetPower","powerstatus":"0"}   // "0" 关，"1" 开

// 查询
{"function":"GETSTATUS"}
```

**上行状态（固件回读）**

```json
{"type":"FourZone","powerStatus":"On","brightNess":"2","currentPowerMode":"AC"}
```

> `type=FourZone` 说明本机键盘为四分区，但当前只实现了整键盘单色写入；分区独立配色是**待验证的扩展点**（见 §6 假设 H2）。

### 4.2 传输层 B：ACPI WMI 请求帧

方法签名（现场 `Get-CimClass` 实测）：

```
MiInterface(InData: UInt8Array[], OutData: UInt8Array[], Reserved: UInt16[])
```

请求帧固定 **32 字节**：

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 1 | 保留（0） |
| 1 | 1 | 操作类型：`0xFA`=Get（250）、`0xFB`=Set（251） |
| 2 | 1 | 保留（0） |
| 3 | 1 | 功能码（见下表） |
| 4..31 | ≤28 | 负载（大端无关，逐字节） |

返回：`OutData[4]` 为 Get 的单字节结果；多字节结果按 `OutData[4..7]` 依次读取（如风扇转速 `lo<<8|hi` 之外的自定义顺序）。

### 4.3 键盘相关功能码（本机实测有效）

| 功能码 | 语义 | 负载 | 读回 |
|---|---|---|---|
| 16 | 键盘灯模式 | `1B`：1=内置流光 2=固定颜色（**0=关：实测被固件忽略**） | `OutData[4]` |
| 17 | 固定颜色 | 3 字节 `R,G,B`（**不接受 12 字节四分区**，见下） | `OutData[4..9]`（6 字节：RGB+PAD） |
| 18 | 亮度 | 1 字节 0–3（**0 才是有效关灯**） | `OutData[4]` |
| 10 | 键盘灯状态 | 无 | 实测恒 0，未使用 |

**实测行为矩阵（2026-11-02 直连 WMI 验证）**

| 操作 | 读回结果 | 结论 |
|---|---|---|
| `SET fn16=2` | `fn16=2` | ✅ 生效 |
| `SET fn17=(0,128,255)` | `fn17=00 80 FF 00 00 00` | ✅ 生效，返回 6 字节（RGB+3 字节填充） |
| `SET fn17=12 字节（R/G/B/W）` | `fn17=FF 00 00 00 00 00 00 00 00 00 00 00` | ❌ 只取前 3 字节，**四分区独立配色不支持** |
| `SET fn16=0`（期望关灯） | `fn16=2`（不变） | ❌ 固件忽略 mode=0 |
| `SET fn18=0`（亮度 0） | `fn18=0` | ✅ **这才是有效关灯路径** |
| `SET fn18=2` | `fn18=2` | ✅ 恢复亮度 |

> ⚠️ 由此发现现有产品缺陷：`SetPower powerstatus=0` 走的是 `fn16=0`（固件忽略）→ **UI 的"关灯"按钮实际无效**。修复方式：关灯改为 `fn18=0`，开灯回写 `fn18=原亮度`（可顺带保留 mode）。

**时序要点（实测踩坑）**：切到"固定颜色"后必须**延时约 500ms 再写颜色**，否则固件丢掉颜色写入（桥接代码 `Thread.Sleep(500)` 即为此）。

**WMI 调用要点（PowerShell 侧踩坑）**：`MiInterface` 的 `OutData`/`Reserved` 是 **out 参数**，`Invoke-CimMethod` 会报 `无效的方法参数`；正确做法是 `ManagementObject` + `GetMethodParameters`，且必须用
`$a.Properties["InData"].Value = [byte[]]$in`（`$a["InData"] = $in` 会被 PSObject 装箱导致 `InvalidCastException`）。

## 5. 分析思路与关键步骤（方法论，可复用）

1. **先圈定边界，再深入实现**：从"谁在跑"入手（进程/服务/PnP 设备），而不是直接反汇编。设备管理器里的 `PNP0C14`（WMI for ACPI）与 `PNP0C09`（EC）是这类灯控的必经之路。
2. **用 WMI 元数据当"地图"**：`Get-CimClass root\WMI MICommonInterface` 直接拿到方法签名，比盲扫二进制快一个数量级。
3. **静态取证确认代码面**：`rea inspect-managed-members` 取类型/方法/字符串，`inspect-managed-native-boundaries` 找 P/Invoke 与动态加载点（WinRing0 属于 LoadLibrary 动态解析，导入表里查不到，这是常见陷阱）。
4. **分层验证**：MQTT 层（消息到达）→ 桥接层（业务日志）→ 固件层（状态回读）逐段确认，避免"看起来成功但没落地"。
5. **对照厂商实现**：反编译源码里的 `WMIEC`/`MyRGBKeyboard` 提供另一种封装（WMI 写 EC RAM），用于判断"当前实现是否等价/是否有能力缺口"。
6. **把假设写成可证伪实验**：例如"fn17 是否支持 4 分区 12 字节负载"，给出确定的最小实验与回滚方法。

### 若继续深挖，建议顺序

1. **修产品缺陷**：关灯改走 `fn18=0`（结论 C7），并在 UI 上同步状态。
2. 流光速度/方向参数：`fn16` 之外是否有独立速度码（当前桥接用软件动画模拟，固件可能原生支持）。
3. 四分区若确有硬件支持，需另找功能码（fn17 已证伪），可对照厂商 `SingleZone`/`FourZone` 类名与 WMI EC-RAM 通道继续找。
4. 关机/合盖状态的灯效持久化：EC RAM 里是否有存储位（需 WinRing0 读 EC，注意读通道可靠性）。
5. 原生驱动层：配置 Ghidra 12.1 后对 `WinRing0x64.sys` 做 IOCTL 分派分析（当前仅导出表级）。

## 7. 风险与限制

### 7.1 硬件/系统风险（高）

- **EC 写入具有粘性**：错误写入可能让风扇/灯控卡在固定状态，软件无法复位，需 EC 断电（关机拔电）恢复。本项目 2026-10-18 已发生过一次（风扇锁 3500）。
- **扩展寻址开关 0x1060 高危**：与遥测线程并发读写会卡死 EC 命令通道，导致 WMI 调用永久阻塞（本项目实测出现过 handler 僵尸线程）。**正常运行绝不碰该寄存器**。
- **读-改-写禁令**：本机 EC 读通道返回恒定幻值（0x12），任何 RMW 都会把垃圾位写回；释放/复位一律直写 0。
- **驱动层面**：`WinRing0x64.sys` 属未签名/易被拦截的内核驱动，蓝屏与杀软/反作弊告警风险实存（Valorant、Faceit 等会直接拒绝）。

### 7.2 分析限制（中）

- **原生代码未反汇编**：Ghidra/IDA 未配置、rizin 在 Windows 不可用，`WinRing0x64.sys` 只做到导出表级；IOCTL 分派与校验逻辑仍属黑盒。
- **托管元数据受限**：REA 的 .NET provider 只做元数据/CIL 锚点，不做 C# 还原；`CCUWinUI.dll` 元数据超预算无法审计。
- **厂商实现不可读**：原服务二进制已不在本机，`decomp_svc` 方法体被剥离，只能参考签名与常量。
- **观测面窄**：无法直接读键盘 LED 亮度/颜色（无传感器），视觉确认依赖人眼；固件状态回读仅能证明"写入被接受"，不等于"物理生效"。

### 7.3 法务/合规（中）

- 逆向本机自购设备的互操作性研究通常可接受，但**分发**厂商二进制、驱动或绕过签名的补丁存在版权与许可风险；本项目仅本地使用、不随包分发厂商文件。
- WinRing0 驱动的再分发违反其许可，仓库中只保留引用路径，不进版本库。

### 7.4 稳定性建议

- 实验一律满足：**单变量、可回滚、先读后写、写后回读**；每次改动前记录 `state.json` 与当前状态。
- 灯控类改动风险低于风扇/功耗类，但仍避免在系统更新、BIOS 升级、睡眠唤醒窗口期做写入实验。

## 9. 灯效实现（软件动画引擎，2026-11-02 完成）

固件只有"固定色 + 单色 RGB"，因此厂商 UI 对 FourZone 机型开放的 6 个效果全部由桥接以软件帧动画实现：
固定 `fn16=2`，按帧改写 `fn17`（约 25–40fps，实测 CPU 占用约单核 1.2%）。

| 效果 | 算法 | 参数 |
|---|---|---|
| Single（选色） | 静态单色，一次写入 | 颜色、亮度 |
| Breathing（呼吸） | 正弦明暗，`0.12 ↔ 1.0`，周期 3.0s × 速度倍率 | 颜色、亮度、速度 |
| Wave（波浪） | 色相在基色 ±75° 往复 + 二次谐波明暗，方向决定相位符号 | 颜色、亮度、速度、方向 |
| Rainbow（彩虹） | 色相 360° 连续流转，3.6s 一圈 × 速度倍率 | 亮度、速度、方向 |
| Mix（混色） | 调色板内插值往返混合；单色时与补色混合 | 多色、亮度、速度、方向 |
| Flash（闪烁） | 方波通断，亮 0.45 周期，1.6s × 速度倍率 | 颜色、亮度、速度 |

**参数映射**：`speed 0-4` → 帧间隔 60/50/40/33/25ms、周期倍率 2.2/1.6/1.15/0.85/0.6；
`light 0-3` → `fn18`；`direction` → 相位方向；`color.ColorBuffer[]` → 主色 + 调色板。

**实测验证（固件 fn17 回读，每模式 10 次采样 / 220ms）**

| 模式 | 不同颜色数 | 观测样例 |
|---|---|---|
| Single | 1 | `FF0000` 恒定 |
| Breathing | 10 | `210000 → 350000 → 600000`（明暗连续变化） |
| Wave | 10 | `8F00A6 → 99008E → AC4800`（色相扫动） |
| Rainbow | 10 | `00FF6E → 1300FF → 86 00FF → FF0004`（全色环） |
| Mix | 10 | `0001FE → 0012ED → 0038C7`（调色板插值） |
| Flash | 2 | `000000 / FF0000`（硬通断） |

速度实时性：同一时刻采样 6 帧，speed0 色相推进约 25°/帧、speed4 约 85°/帧 —— 调参即时生效，无需重进页面。

**同时修复的两个缺陷**

1. 关灯：`fn16=0` 无效 → 改 `fn18=0`；开灯回写原亮度（并修掉了"状态回读把用户亮度覆盖成 0"的问题，实测 3 → 关(0) → 开(3) 正确恢复）。
2. 参数不生效：旧实现只在"效果名变化"时才重启循环，速度/颜色调整被忽略 → 改为参数对象原地更新，循环下一帧即读取新值。
